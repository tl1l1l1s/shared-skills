# 계획 관리

## 원본과 최초 사용

`workspace/tasks.md`가 개인 월간·주간 계획과 작업 상태의 단일 원본이다. 오늘 할 일은 inbox 맨 위 할 일 칸에 두고 inbox와 Daily Log는 실제 활동의 근거다. Notion은 주간 요약과 보존할 경험을 게시하는 곳이다.

처음 사용할 때 tasks.md가 없으면 아래 형식으로 만든다. 기존 inbox, 최근 계획·일지에서 명시된 목표·마감·상태를 출처와 함께 가져온다. 과거 계획에 있었다는 이유만으로 이번 주 약속으로 확정하지 않는다.

```md
# 작업 목록

확정 월: 미확정
확정 주: 미확정

## 주간 조정 상태
| ISO 주 | 상태 | 갱신일 |
|---|---|---|

## 월간 결과
| ID | 기간 | 원하는 결과 / 완료 기준 | 상태 | 출처 |
|---|---|---|---|---|

## 주간 약속
| ID | ISO 주 | 월간 결과 ID | 이번 주 완료 기준 | 상태 | 출처 |
|---|---|---|---|---|---|

## 작업
| ID | 주간 약속 ID | 작업 / 다음 행동 | 마감 | 상태 | 근거 / 확인 필요 |
|---|---|---|---|---|---|

## 고정 일정
| 날짜·시각 | 일정 | 출처 |
|---|---|---|

## 재계획 제안
```

ID는 생성 후 유지한다(M1/W1/T1 등). 연결할 상위 목표가 없으면 `미연결`로 남기고 관계를 지어내지 않는다. 작업 상태는 대기/진행/막힘/완료/보류/취소로 구분하고 월간 결과와 주간 약속의 상태도 같은 값을 쓴다. 가지 못한 고정 일정에 딸린 작업은 `불참`으로 둔다. 마감 칸은 `M/D HH:MM`으로 쓰고 해가 다르면 연도를 붙이며 없으면 `-`다. 고정 일정의 날짜·시각은 `YYYY-MM-DD HH:MM`이다. 증거가 없다는 이유로 미실행·취소로 단정하지 않는다. 상태 변경은 기존 행에 반영한다. 완료·취소된 행을 삭제하지 않는다. standup의 날짜 전환과 `/close-daily`가 완료, 취소, 불참 행과 지난 고정 일정을 `workspace/tasks-done.md`로 옮긴다. 새 ID는 두 파일을 통틀어 가장 큰 번호 다음이며 옮긴 ID를 재사용하지 않는다.

## 주간 재계획

`/review-weekly`는 실행일이 속한 ISO 주를 검토하고 다음 주를 계획한다. 사용자가 특정 주를 지정하면 그 주를 대상으로 한다. `/review-weekly 이번 주`에서는 지난주를 검토하고 이번 주를 계획한다. 기본 `/plan-daily`는 `templates/weekly-adjust.md`에 따라 그 주 첫 실행에서 짧은 조정만 한다. 아래 상세 재계획·요약 게시를 자동으로 실행하지 않는다. 같은 기간의 확정안이 있으면 새로 만들지 않고 이후 변경만 제안한다.

1. 월간 결과와 이번 주 약속을 실제 근거와 대조한다. 완료, 남은 일, 막힌 일, 기록이 없어 모르는 일을 구분한다.
2. 다음 계획 기간의 고정 일정·마감·사용자가 말한 가용 시간을 확인한다. 가용 시간을 모르면 분량을 잠정안으로 표시한다.
3. 미완료 항목마다 유지/축소/보류/취소 중 하나와 이유를 제안한다. 전체 자동 이월을 하지 않는다. 축소할 때 새 완료 기준과 남는 범위를 함께 표시한다.
4. 월간 결과와 연결된 주간 완료 기준, 그에 필요한 다음 행동을 제시한다. 필요 시간과 가용 시간이 충돌하면 뺄 항목을 명시한다. 월 목표가 어려워졌으면 범위 또는 기한 조정안도 함께 제안한다.
5. 사용자 답변으로 선택된 변경만 확정한다. 답이 없으면 `재계획 제안`에 저장하고 기존 약속·마감·확정 기간을 유지한다. 사용자가 직접 지시한 변경은 다시 승인받지 않는다. 확정 시 영향받는 작업의 연결도 갱신한다. 새 주 제안을 저장할 때 이전 주 제안은 지운다. `templates/weekly-adjust.md`의 주차별 상태도 갱신한다(제안/확정/보류). 일요일에 다음 주를 확정할 때도 다음 주 ISO 주를 기록하고 이번 주 상태를 보존한다. 승인하지 않은 제안은 확정으로 기록하지 않는다.

월 경계에서는 지난달 미완료 결과의 처리와 새 월간 결과·완료 기준을 같은 방식으로 정한다. 새 월이라는 이유만으로 기존 목표를 완료·취소 처리하지 않는다.

## 주간 요약 게시

요약은 `workspace/weekly/YYYY-Www.md`에 저장한다. 해당 주의 완료 결과, 남은 일·불확실한 사실, 재계획 제안/확정 여부, 월간 목표에 미치는 영향을 담는다. 재실행 시 해당 주 파일을 읽고 갱신하며 기존 근거와 게시 URL을 보존한다.

Notion 게시는 선택이다. Notion이 미설정이면(`collectors/notion.md`) 게시를 건너뛰고 미게시로 표시한다. 로컬 저장 후 게시할 내용을 미리 보여주고 사용자 승인을 받아, Goal DB의 같은 주 Weekly 페이지에 `주간 요약` 섹션을 갱신한다. 페이지가 없으면 승인된 게시 범위에서 생성한다(`config/notion.md`의 속성 정의 사용). 기존 체크리스트와 다른 본문은 보존한다. 재시도 시 저장된 URL 또는 정확히 같은 주 페이지를 먼저 조회해 중복 생성을 피한다. 후보가 여럿이면 대상을 확인한다. 성공한 페이지 URL은 로컬 요약에 남기고, 실패하면 미게시로 표시한다. 게시 실패나 승인 대기는 로컬 계획 완료를 막지 않는다.

경험 정리는 `/review-weekly career`에서 수행한다. 일상 마감에서는 Notion에 쓰지 않으며, Work Item/Trouble/Portfolio 후보는 로컬 근거를 보존한 뒤 이 모드에서 검토·게시한다.
