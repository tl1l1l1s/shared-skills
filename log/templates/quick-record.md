# 기록 처리 (standup과 log 공통)

사용자가 대화로 한 일·일정·시간을 말했거나 inbox에 새 메모나 할 일 칸의 처리할 줄이 있을 때 읽는다. 로컬 파일만 쓴다. 완료·일정·소요처럼 명확한 사실만 반영하고 성과나 WHY는 사용자가 적은 것만 옮긴다.

## inbox 형식

`workspace/inbox.md`는 맨 위 할 일 칸과 그 아래 날짜별 자유 메모다. 태그·표·예상 시간을 요구하지 않는다.

- 날짜 제목은 기록 기준일이다. 문장 안의 날짜는 그 날짜의 일정·마감으로 읽고 상대 날짜는 기준일에 연결한다. 기준일이 없으면 `날짜 확인 필요`에 두고 오늘이나 어제로 분류하지 않는다.
- 완료·진행·막힘·일정·새 목표·결정 이유를 문장에서 구분한다. “할 일”, “하고 싶음”, “이번 주에 …하자”는 신규 목표 후보다. 기존 작업과 일치하면 그 작업을 갱신한다. 모호한 희망은 확정 약속으로 바꾸지 않는다.
- 시간은 선택이다. 할 일 줄 아래 들여 쓴 줄의 `14:00~14:30, 14:50~15:20`은 사용자가 직접 작업한 구간이다. 병렬·AI 대기·대략적인 시간은 표현 그대로 남긴다. 반영은 `templates/time-recording.md`를 따른다.
- inbox는 할 일 칸과 날짜별 메모를 끝까지 읽는다. 저장은 변경된 행·섹션만 갱신하고 원문은 길어도 자르지 않는다.

## 대화로 기록하기

- “문서 다 썼어”, “한 시간쯤 걸렸어”, “오늘 거의 못 했어”, “이건 이번 주에 안 할래”, “금요일 13시에 일정 생겼어” 같은 말을 별도 명령 없이 받는다. 실제 기록 요청과 설명용 예시·가정은 구분하며 메타 대화를 작업 실적으로 기록하지 않는다.
- 사용자 발화는 inbox에 넣지 않는다. 아래 절차에서 inbox에 쓰고 지우는 부분만 건너뛰고 원문은 발화 그대로 2단계에 따라 일지에 보관한다. 실제 수행일이 명시돼 있으면 함께 보존하고 미언급된 과거 수행일을 지어내지 않는다. “오늘”과 “어제”는 `CLAUDE.md`의 하루 경계를 따른다. “금요일”, “내일”은 오늘 기준으로 날짜를 계산해 답에 적는다. 이미 파일에 쓴 메모를 처리하는 요청이면 다시 추가하지 않는다.
- “끝냈어”는 직전에 제시한 현재 행동이 하나로 식별될 때만 연결한다. 그 행동이 큰 작업의 일부이면 해당 단계만 완료하고 전체 목표를 완료로 바꾸지 않는다. 여러 작업 중 무엇인지 불명확하면 원문을 저장하고 질문 한 번만 한다. 답이 없으면 미확정으로 남긴다.
- “이번 주에 안 할래”는 이번 주 약속에서 보류하는 뜻이며 영구 취소로 해석하지 않는다. “오늘은 30분밖에 없어”는 가용 시간 변경이지 30분 작업했다는 뜻이 아니다. 휴식·미진행은 시간 0으로 계산하거나 해명을 요구하지 않는다.

## 원문 보존과 재실행

메모 단위로 처리한다. 같은 날짜의 다른 메모가 불명확해도 명확한 메모는 진행한다. 단, 한 메모에 불명확한 부분이 있으면 안전하게 반영할 사실만 적용하고 원문은 pending으로 유지한다.

1. **접수:** inbox의 처리할 실제 메모 바로 위에 `<!-- memo: {UUID} -->`를 붙여 먼저 저장한다. 대화 발화는 inbox에 쓰지 않고 UUID만 만든다. UUID는 표준 UUID 생성기로 만들고 재시도에는 기존 값을 사용한다. 기존 메모의 문구·날짜·순서는 바꾸지 않는다. 동일 문장을 나중에 다시 입력해도 별도 사건이면 새 ID다. 기존 발화의 재처리는 같은 ID다.
2. **원문 보관:** 수행일이 명확하면 그 날짜, 아니면 기록일의 `workspace/daily/YYYY-MM-DD.md`에 `## 빠른 기록` 아래 같은 ID, 원문, 기록일/수행일 구분, `state: pending`을 저장한다. 한 메모는 `<!-- memo: {UUID} -->` 줄, `- 기록일 YYYY-MM-DD / 수행일 YYYY-MM-DD / state: pending` 줄, `>`로 인용한 원문 순으로 적는다. 새 파일이면 `<!-- daily-kind: quick -->`를 붙인다. 기존 일지의 다른 내용은 덮어쓰지 않는다. 날짜를 알 수 없는 기존 메모는 inbox에 남겨두고 확인되지 않은 날짜로 일지를 만들지 않는다.
3. **명확한 사실 반영:** tasks.md의 해당 작업/일정에 변경을 적용한다. 근거 칸은 마감과 상태의 출처 한 줄로 두고 새 사실이 오면 덮어쓰며 메모 ID는 적지 않는다. 지난 경과는 일지에 있다. 새 작업 생성 전 같은 요청이 이미 반영됐는지 확인한다. 새 작업의 번호는 `grep -ohE '^\| *T[0-9]+ *\|' workspace/tasks.md workspace/tasks-done.md 2>/dev/null | grep -oE '[0-9]+' | sort -n | tail -1`로 두 파일의 ID 칸에서 최대 번호를 확인한 다음 번호다. 결과가 비어 있으면 T1이다. 실제 진전이 확인되면 원문 근거가 있는 수행일만 마지막 진전일로 남긴다. 단순 언급이나 계획 변경으로 진전일을 새로 찍지 않는다.
4. **시간 반영:** 시간이 언급된 메모만 `templates/time-recording.md`를 읽고 반영한다. estimates의 비고에 같은 메모 ID를 넣고 이미 반영된 경우 중복 행을 추가하지 않는다. 정정은 원래 ID·행을 참조하는 정정 기록으로 남긴다.
5. **완료 및 정리:** 원문과 필요한 작업·시간 반영을 다시 확인한 뒤 일지의 해당 메모를 `state: done`으로 바꾼다. inbox에서 온 메모는 그 뒤에만 inbox에서 같은 ID와 원문이 일치하는 메모를 제거한다. 대화 발화는 inbox에 없으니 제거하지 않는다. 원문이 수정됐으면 지우지 말고 새 ID의 정정 메모로 이전 ID와 연결해 보존한다. 다른 날짜·미확인 기록과 사용자가 추가한 메모는 그대로 둔다.

실패하거나 확인 대기면 pending 원문을 유지한다. 재실행은 inbox의 ID와 그 메모의 일지·작업·시간 행만 대조하고 빠진 단계부터 재개한다. 대화 발화는 일지에 pending으로 남은 메모에서 재개한다. done인 일지와 반영 결과가 확인되면 같은 사실을 다시 반영하지 않고 inbox 잔여분만 정리한다. 삭제 전에는 inbox를 다시 읽어 다른 변경이 없는지 확인한다.

자동 정리는 미리 읽은 inbox의 명확한 메모만 대상으로 한다. 새 기록도 변경도 없으면 아무 파일도 쓰지 않는다. 밀린 자료를 모두 처리하려고 날짜 확인 질문을 연달아 하지 않는다. 이미 물은 미확인 사항은 오늘 행동에 영향을 주지 않으면 재질문하지 않는다. 자동 정리 실패도 오늘 계획을 막지 않는다.

## 오늘 할 일 칸

`workspace/inbox.md` 맨 위 안내 문단 바로 아래의 체크리스트다. 사용자는 이 칸을 보며 하루를 진행하고 체크로 완료를 기록한다. 칸은 메모가 아니며 날짜별 메모는 그 아래에 쌓인다.

```md
<!-- todo: YYYY-MM-DD -->
## 오늘 할 일 (YYYY-MM-DD)

- [ ] 12:00 우체국 (T4)
- [ ] 13:15 관리사무소 전화 (일정)
- [x] 분기 보고서 초안, 예상 90m (T10) <!-- rec: 1A2B3C4D -->
  - 13:00~13:10, 14:00~14:40 <!-- rec: 1A2B3C4D -->
- [ ] 통계 교재 2장 읽고 정리, 참고 60m (T9)
  - 13:10~14:00
- [ ] 영어 듣기 1회분 풀이 (T21)
<!-- /todo -->
```

**쓰기:** 고정 일정을 시각순으로 먼저 적고, 이어서 오늘 마감인 줄을 마감 시각순으로 적고, 이어서 나머지 할 일을 적고, 마지막에 AI에게 맡겨 사용자가 시간을 내지 않는 작업을 `AI 진행`을 붙여 적는다. 나머지 할 일의 순서는 사용자가 칸에서 직접 조정하므로 에이전트는 우선순위를 판단하지 않는다. 날짜 전환 때 어제 칸에 남아 있던 줄은 어제 순서를 유지하고 새 줄은 뒤에 붙인다. 여러 단위로 나뉘는 할 일(문제 여러 개, 책이나 장 여러 개)은 단위마다 한 줄이며 분할표가 있어도 오늘 분량만 적지 않고 남은 단위를 전부 적는다. `AI 진행` 줄은 사용자가 AI에게 맡겼다고 말해 tasks.md 근거 칸에 `AI 진행`이라고 적어 둔 작업이며 예상 시간을 적지 않는다. 줄 끝에는 작업 ID를, ID 없는 고정 일정에는 `(일정)`을 붙인다. 같은 날 다시 쓸 때는 기존 줄·체크·하위 줄·사용자가 추가한 줄을 그대로 두고 빠진 항목만 추가한다.

할 일 줄을 새로 쓸 때 ID 앞에 예상 시간을 적는다. 사용자가 말한 예상이 있으면 `예상 30m`이다. 없으면 `workspace/estimates.md`를 새 줄의 작업 ID와 종류 낱말(문서, 교육, 풀이, 장)로 한 번 grep해서 같은 작업 ID의 행, 없으면 같은 종류의 최근 행 최대 3개를 고르고 실제 칸의 중간값을 `참고 60m`으로 적는다. 실제가 숫자인 작업 행만 쓰고 고정 일정 행, `측정 불가`, `배분 미상`, 범위 추정은 뺀다. 매일 반복하는 묶음 작업(위 예시의 영어 듣기 풀이처럼)은 ID가 아니라 줄의 단위 이름(영어 듣기 1회분)으로 찾는다. 비교 가능한 실제가 없으면 적지 않는다. 고정 일정 줄에는 적지 않는다.

**처리:** 실행할 때마다 칸을 먼저 읽고 처리할 줄이 있으면 쓰기 전에 처리한다. 처리할 줄은 `rec` 표식이 없는 `[x]` 줄, 작업 ID나 `(일정)` 표시가 없는 들여 쓰지 않은 줄(사용자가 추가한 줄), 아래 규칙에 해당하는 하위 줄이다. 탭이나 공백으로 들여 쓴 하위 줄은 체크박스가 붙어 있어도 새 할 일이 아니라 위 줄에 딸린 기록이다. 한 번에 모은 줄을 메모 하나로 보고 위 `원문 보존과 재실행`을 따르되 접수 단계 대신 칸의 줄을 원문으로 쓰고 정리 단계에서 줄을 지우지 않는다. 원문 보관 날짜와 완료 날짜는 칸 날짜다. 칸 날짜가 오늘보다 이틀 이상 이르면 완료 날짜를 한 번 묻고 답이 올 때까지 pending으로 둔다.

- 작업 ID가 있는 `[x]`: 그 줄의 단위만 완료로 반영한다. 줄이 작업 전체를 가리킬 때만 작업을 완료로 바꾼다.
- 고정 일정 줄의 `[x]`: 다녀온 것으로 일지에 기록하고 연결된 작업이 있으면 그 작업에도 반영한다. 고정 일정 표의 행은 바꾸지 않는다.
- 사용자가 추가한 줄: 같은 요청이 없으면 tasks.md에 새 작업으로 등록하고 줄 끝에 새 ID를 붙인다. 체크돼 있으면 완료로도 기록한다.
- 하위 줄의 시각 구간(`14:00~14:30, 14:50~15:20`)이나 소요 시간(`30분`)은 사용자가 위 작업에 직접 쓴 시간이다. `rec` 없는 하위 줄은 위 줄이 `[x]`이면 이번 실행에서, 체크되지 않았으면 날짜가 바뀌어 칸을 바꾸기 전에 위 줄과 같은 메모로 처리하고 `templates/time-recording.md`대로 기록한다. 체크되지 않은 위 줄은 완료 없이 진행과 시간만 기록한다. 끝 시각이 없는 구간은 계산하지 않고 원문만 남긴다. 시간이 아닌 하위 줄은 위 줄에 대한 메모로 읽는다. 처리한 하위 줄 끝에도 `rec`를 붙인다.
- 하위 줄에 `(완료)`가 있으면 위 줄이 체크되지 않았어도 `[x]`로 바꾸고 체크된 줄처럼 처리한다. `(일부 완료)`는 진행만 기록한다.
- 줄의 `예상`·`참고` 값은 시간 행의 예상 칸으로 옮긴다. 구분은 `templates/time-recording.md`를 따른다.
- 반영을 마친 `[x]` 줄 끝에 `<!-- rec: {메모 ID 앞 8자리} -->`를 붙인다. `rec`가 있는데 체크가 풀린 들여 쓰지 않은 줄은 정정 후보로 보고 한 번 묻는다. 답이 오기 전까지 기록은 그대로 둔다.

대화로 알린 완료가 칸의 한 줄과 하나로 맞으면 그 줄도 `[x]`로 바꾸고 같은 메모 ID로 `rec`를 붙인다.

## 보드 파일

`workspace/dashboard.md`는 standup이 매 실행 끝에, log는 파일을 바꾼 뒤에 아래 형식으로 다시 쓴다. `/log` 첫 화면에서도 본다. 세 칸은 브리핑과 같은 내용이다. 세 칸의 줄 머리는 `##` 제목이 아니라 굵은 목록 줄로 쓰고 `밀린 작업`만 `##` 제목과 번호 목록으로 쓴다. 항목은 줄 머리 아래 들여 쓴 줄에 하나씩 `시각 내용` 순으로 쓴다. 오늘이 아닌 날짜는 `3/17`처럼 앞에 붙이고 마감 시각은 `~17:00`, 시작 시각은 `15:00`으로 쓴다. 작업 ID와 `(일정)` 표식은 적지 않는다. 완료한 항목은 빼고 항목이 없는 줄 머리는 생략한다. 밀린 작업은 tasks.md의 대기·진행 작업 전부를 오늘 고정 일정, 마감 임박, 그 밖의 순으로 같은 꼴로 한 줄씩 적고 완료·취소·불참은 뺀다.

```md
# YYYY-MM-DD 보드

- **오늘 마감**
  - ~18:00 분기 보고서 초안 제출
- **일정**
  - 13:00 안경점
- **놓치면 안 되는 것**
  - 3/17 ~17:00 가계부 앱 소개 자료 제출
  - 3/21 15:00 독서 모임

## 밀린 작업
1. ~18:00 분기 보고서 초안 제출
2. 가계부 앱 내보내기 오류 수정
```

## 응답

기록 반영 사실을 한 줄로 알린다. 이어서 할 행동이 바뀌었을 때만 다음 행동 한 줄을 덧붙인다. 작업 ID·처리 표식은 사용자에게 입력하도록 요구하지 않고 답할 때도 작업을 ID가 아니라 이름으로 부른다. 새 기록 때문에 주간·월간 계획 전체를 다시 출력하지 않는다. 실행 없이 문구만 만들어 놓고 “저장했다”고 말하지 않으며 부분 저장·미확정은 구분해서 알린다.
