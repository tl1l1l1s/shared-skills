# cover-letter

회사 자기소개서를 함께 쓰는 Claude Code 스킬. 회사·산업 조사부터 소재 후보, 구조 설계, 초안, 다듬기까지 함께 한다. 검증한 프롬프트 네 개(조사, STAR 재작성, 다듬기 검증, 외부 검토)를 원문 그대로 재현해서 세션이 바뀌어도 동작이 흔들리지 않는다.

특정 프로젝트나 프레임워크에 기대지 않는 독립 스킬이라, 이 폴더 하나만 있으면 된다.

## 쓰는 법

저장소를 받고 이 폴더를 Claude Code가 스킬로 잡게 복사한다.

```bash
git clone https://github.com/tl1l1l1s/shared-skills.git
mkdir -p ~/.claude/skills
cp -r shared-skills/cover-letter ~/.claude/skills/cover-letter
```

작업하는 프로젝트의 `.claude/skills/`에 둬도 된다.

복사해서 쓰는 게 맞다. `STYLE_GUIDE.md`, `QUALITY_BAR.md`, `BANNED_WORDS.md`, `REVISION_LOG.md`는 쓸수록 본인 문체와 첨삭 이력이 쌓이는 데이터 파일이라, 복사본에서 각자 자라야 한다. 저장소를 심볼릭 링크로 걸면 갱신은 편하지만 본인 데이터가 저장소 안에 쌓이고 `git pull` 때 충돌한다.

나중에 저장소가 갱신되면 데이터 파일 넷을 뺀 나머지(`SKILL.md`, `prompts/`, `reference/`, `scripts/`)만 덮어쓴다. 쓰는 동안 승격 규칙으로 `reference/` 파일을 고친 적이 있으면 그 파일은 덮어쓰지 말고 diff를 보고 합친다. 데이터 파일에 든 일반 규칙의 갱신도 같은 식으로 diff를 보고 가져온다.

**어디서 실행하나.** 작업물은 Claude Code를 켠 위치의 `자소서/` 폴더에 쌓인다. 자소서를 모아 둘 폴더를 하나 정해서 거기서 켜면 된다. 홈에서 켜면 `~/자소서/`가 생기니 주의한다. 개인 내용이라 그 폴더는 gitignore에 넣는 걸 권한다.

**필요한 것.** Stage 2 회사 조사에 웹 검색이 필요하다. 전자공시처럼 정적 검색으로 안 잡히는 자료는 브라우저 자동화로 보완한다. Notion은 선택이다(아래 참고). 글자 수와 금지어 후보를 세는 `scripts/check.py`는 python3로 돈다. 외부 검토(`prompts/external-review.md`)는 Codex CLI 같은 다른 모델이 있을 때만 쓰는 선택 단계다.

호출은 이렇게 한다. "OO 자소서 쓰자", "이 문항에 어떤 경험 쓰면 좋을까", "다듬기 돌려줘".

## 처음 쓰기 전 (부트스트랩)

- **문체** `STYLE_GUIDE.md`에 기본 문체가 이미 채워져 있어서 샘플 없이도 바로 쓸 수 있다. 본인이 잘 썼다고 생각하는 자소서를 한 편 이상 주면 그 목소리를 뽑아 문체 절만 덮어쓴다.
- **소재** 이 스킬의 유일한 필수 준비물이다. 본인 프로젝트·경험을 **에피소드 단위로** 문제·행동·결과를 적어 한 곳에 모아 둔다. Notion 페이지든 로컬 마크다운 파일이든 된다. 구체적인 구성은 `reference/storage.md`의 소재 구성 절에 형식이 있다. 소재가 없으면 스킬이 후보를 못 뽑으니(없는 경험을 지어내지 않는다) 먼저 정리하자고 되묻는다.
- **금지어** `BANNED_WORDS.md`에 AI 냄새 나는 표현의 시작 목록이 있다. 쓰면서 본인 취향으로 더한다.

## 이 스킬이 들고 오는 것

문체 데이터와 별개로, 실제 첨삭을 반복하며 뽑아낸 규칙이 스킬 안에 들어 있다.

- **AI 구문 리듬 안티패턴** (`STYLE_GUIDE.md`) 단어 금지어로는 안 잡히는 구문 결. A가 아니라 B 대조, 명사형 종결 반복, 사동 우회, 상투 비유, 슬로건 마무리.
- **작위성 판별 규칙** (`STYLE_GUIDE.md`) AI가 쓴 자소서에서 사람들이 실제로 걸리는 건 어휘보다 서술 논리다. 교훈 회수 문장, 인과 없는 브리지, 결론을 알고 재구성한 서사, 추상 역량명, 감정 선언 선행, 독자 몫 침범, 이력서식 나열 일곱 가지를 걸러낸다. 다듬기 패스에서 문장마다 던지는 검사 질문 세 개는 `prompts/polish-check.md`에 있다.
- **분량과 문단 설계 원칙** (`reference/structure-codesign.md`) 경험의 갈래가 소제목 유무를 정한다, 자유양식 도입은 컨셉 하나로, 기술 밀도를 급변시키지 않는다, 모든 문단이 중심축 위에 있는지 검사한다.

앞의 두 가지는 목소리와 무관한 일반 규칙이라 문체를 재보정해도 덮어쓰지 않는다. 세 번째는 구조·분량 피드백이 쌓이면 재보정 대상이 된다(`REVISION_LOG.md`의 승격 규칙).

## 흐름

1. 회사, 직무, 문항, 블라인드 여부 확인
2. 회사·산업 조사 (이해용, 산업 수치는 문장에 안 넣음)와 공개 합격 자소서 수집
3. 문항 해석 (평가 의도, 반드시 담을 것, 지양 신호)
4. 소재에서 문항별 경험 후보 3개와 매핑 이유 (에피소드 단위)
5. 구조 공동 설계 (문항마다 확인받고 초안으로)
6. 초안 (STAR 재작성, 블라인드면 지원자 식별 정보를 대명사로)
7. 반복 첨삭 + 사용자가 부를 때만 다듬기 패스 (AI말투 제거, 금지어 치환, 확정 전 검사까지 한 번에)

확인은 정해진 다섯 곳에서만 받는다(입력, 조사와 문항 해석, 소재, 문항별 구조, 확정 전 검사의 지적). 초안은 구조를 확인받으면 이어서 낸다. 진행 여부 확인은 선택지 다이얼로그(AskUserQuestion)로 받아서, 답이 오기 전에 답을 가정하고 진행하지 않는다. 확정한 답안은 `자소서/_참고/`에 기초 문항 답안으로 쌓여 다음 회사 때 재사용한다.

작업물은 실행 위치의 `자소서/` 폴더에 쌓인다(개인 내용이라 gitignore 권장). 자세한 규칙은 `SKILL.md`와 `reference/`.

## Notion 없이 쓰기

소재를 로컬 마크다운 파일로 두면 Notion 없이도 이 스킬을 쓸 수 있다. 완료본도 로컬 `자소서/`에 그대로 두면 된다.
