# 저장 위치와 규칙

이 스킬은 실행 위치의 `자소서/` 폴더에 작업물을 쌓는다. 자산을 종류가 아니라 생애주기로 나눠 둔다.

## 지도

| 자산 | 성격 | 위치 |
|------|------|------|
| 소재 (프로젝트·활동, 자기소개·성격) | 읽기 원천 | Notion 소재 페이지 또는 로컬 마크다운 파일 (아래 소재 설정) |
| 모범 답안, 기초 문항 답안, 좋은 샘플 | 참고·재사용 | `자소서/_참고/` |
| 이력서 스냅샷 | 참고·대조 | `자소서/_참고/이력서-스냅샷.md` (있을 때만. `reference/final-gate.md` 4번이 읽음) |
| 사실 정정 대장 | 참고·대조 | `자소서/_참고/사실-정정.md` (사용자가 확인해 정한 사실을 `- {프로젝트나 소재}: {정한 사실} ({확인한 날짜})` 한 줄씩. 사실을 처음 정할 때 만든다. `reference/final-gate.md` 4번과 `reference/material-candidates.md`가 읽음) |
| 문체 샘플, 블라인드 판정 | 참고·기준 | `자소서/_참고/문체-샘플.md`, `문체-블라인드-{날짜}.md` (`reference/style-extraction.md` 블라인드 판정 절) |
| 합격 구조 패턴 | 참고·선택지 | `자소서/_참고/합격구조.md` (`reference/revision-loop.md` 합격 자소서 절) |
| 고른 합격 자소서 | 참고·재사용 | `자소서/_참고/합격자소서/` (사용자가 고른 글만 한 편에 파일 하나. 회사 폴더의 `합격자소서-참고-*.md`는 고르기 전까지 두는 후보다) |
| 회사 조사 노트 | 이해용 배경 | `자소서/{회사}/조사.md` |
| 입력 노트 (회사·직무·문항·분량·블라인드·마감·문항 해석) | 세션 복원용 | `자소서/{회사}/입력.md` |
| 작업 중 자소서 | 산출물(작업) | `자소서/{회사}/자소서.md` |
| 이력 항목, 경력기술서, 제출본 이력서 | 산출물(작업) | `자소서/{회사}/` (`reference/resume-items.md`) |
| 완료된 자소서 | 보관 | 로컬 `자소서/{회사}/`에 그대로 (원하면 Notion에도) |
| 문체 가이드, 품질 기준, 피드백 로그, 금지어 목록, 프롬프트 4종, `scripts/check.py` | 스킬 내부 | 스킬 폴더 |

폴더가 없으면 만든다. 작업 중 자소서는 문항별 As-Is/To-Be 구조(`reference/revision-loop.md`)로 둔다.

## 소재 설정

소재는 두 가지 중 하나로 둔다.

- **Notion 페이지** 본인 Notion에 프로젝트·경험을 정리한 페이지. 연결된 Notion 커넥터(claude.ai 커넥터라면 `mcp__claude_ai_Notion__*`)로 읽는다.
- **로컬 마크다운 파일** 같은 내용을 로컬 파일로 둬도 된다. 이러면 Notion 없이도 이 스킬을 쓸 수 있다.

처음 쓸 때 소재 위치를 사용자에게 확인하고 `자소서/_참고/소재-위치.md`에 적어 두면 다음부터 재사용한다. Notion이든 로컬이든 한 곳에 몰아 둔다. 여러 파일에 흩어져 있으면 어디까지 읽어야 할지 매번 물어야 한다.

### 소재 구성

Stage 3이 에피소드 단위로 후보를 뽑으려면 소재 쪽에서 에피소드가 갈라져 있어야 한다. 아래 구성이면 충분하다.

```
## 프로젝트·활동

### {프로젝트 이름}
- 한 줄 소개: 무엇을 만들었나, 역할과 기간
- 기술적 활동
  - {에피소드 제목} — 문제 / 내가 한 행동 / 결과(가능하면 수치)
  - {에피소드 제목} — 문제 / 행동 / 결과
- 비기술적 활동
  - {에피소드 제목} — 갈등·소통·리더십 상황 / 행동 / 결과

## 자기소개·성격
- 한 줄 소개
- 장점 / 단점
- 중요하게 생각하는 것
- 이 직무를 택한 이유
```

핵심은 **에피소드마다 문제·행동·결과 세 줄**이 있는 것이다. 프로젝트 이름과 스택만 적어 두면 Stage 3이 후보를 못 나눈다. 비기술적 활동은 갈등·협업 문항의 유일한 재료이니 빼지 않는다.

## Notion 쓰기 (소재를 Notion으로 두거나 완료본을 Notion에 저장할 때만)

- 연결된 Notion 커넥터를 쓴다. 401/미인증이면 우회하지 말고 재인증을 요청한다. 429면 잠깐 쉬었다 재시도한다.
- **쓰기는 사용자 승인 후에만.** 승인 없이 Notion에 쓰지 않는다. 저장했다고 거짓 보고하지 않는다.

## 완료된 자소서 저장

문항이 다 확정되면 완료본을 어디에 둘지 사용자와 정한다. 기본은 로컬 `자소서/{회사}/`에 그대로 두고, 원하면 Notion에도 저장한다(승인 후).

- Notion에 저장할 때 한글 본문은 유니코드 이스케이프로 바꾸지 않고 원문 그대로 보낸다. 이스케이프로 옮기면 받침이 바뀐 오타가 생길 수 있다. 저장한 뒤 페이지를 다시 읽어 파일 As-Is와 문단 단위로 대조하고, 대조한 범위를 사용자에게 알린다.
- 저장했으면 `자소서.md` 맨 위(첫 문항 제목 앞)에 저장한 위치를 한 줄 적는다.

## 기초 문항 답안 쌓기

사용자가 어떤 문항의 답을 앞으로도 거의 그대로 쓰겠다고 하면, 그 답을 `자소서/_참고/모범답안.md`에 기초 문항 답안으로 저장할지 확인하고 저장한다. 이렇게 쓸수록 기초 문항 답안이 채워지고 다음 회사 때 재사용된다(`reference/material-candidates.md`의 모범 답안 분기).

모범 답안과 좋은 샘플의 출처는 사용자다. 사용자가 직접 보내 주거나, 위처럼 사용자가 확정한 답이 쌓여서 생긴다. 스킬이 임의로 만들지 않는다.

## 모범 답안 인덱스

`_참고/모범답안.md`의 각 답안은 머리에 아래 필드를 단다. 이걸로 새 문항과 매칭한다.

- 원 문항(성격), 직무 적합, 분량(자수), 블라인드 여부, 사용 에피소드, 승인 상태(사용자 확정 여부)

모범 답안과 기초 문항 답안은 같은 은행의 항목이다. 기초 문항 답안은 그중 지원동기나 장단점처럼 표준 문항용으로 반복 재사용되는 것을 가리킨다.
