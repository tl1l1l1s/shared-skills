# Stage 6.5 — 확정 전 통과 검사

다듬기 패스에 묶여 돈다. 다듬기가 문장을 고치고 나면 이 검사가 답안 전체를 확정 기준으로 본다.

## 언제 도는가

- 다듬기 패스(`prompts/polish-check.md`)에서 사람이 쓴 버전을 To-Be에 넣은 뒤
- 사용자가 검사만 따로 부를 때

사용자가 확정이라고 하면 이 검사를 다시 돌리지 않고 승격한다.

문항이 여럿인 건은 문항마다 끊지 않는다. 다듬기 패스와 함께 전 문항을 한 번 돌고 결과도 문항별로 나눠 한 번에 낸다.

## 무엇을 보는가

### 1. 문항 요구 커버

`자소서/{회사}/입력.md`의 문항 해석과 대조한다. 배치는 Stage 4에서 이미 판정했으니 여기서는 **첨삭을 거치는 동안 사라지지 않았는지**를 본다.

- 반드시 담을 것이 전부 본문에 남아 있는가
- 하위 요구사항이 전부 남아 있는가
- 지양 신호에 걸리는 내용이 들어가 있지 않은가
- 문항이 여럿이면 다른 문항과 같은 약속이나 같은 사례 설명을 되풀이한 자리가 없는가 (`reference/structure-codesign.md` 문항 사이 역할)

요구 하나가 첨삭 중에 빠져도 이해도 점검이나 AI말투 검사로는 안 걸리기 때문에 여기서 다시 본다.

### 2. 뽑을 이유 한 줄 복원

본문만 읽고 이 사람을 뽑을 이유를 한 줄로 적어 사용자에게 보여준다. 문항 해석의 한 메시지와 대조한다.

- 한 줄이 안 나오면 요점이 없는 것이다. 어느 문단이 메시지를 흐리는지 함께 짚는다.
- 한 줄은 나오는데 문항 해석의 한 메시지와 다르면 소재나 구조가 어긋난 것이다. 어느 쪽을 고칠지 사용자에게 묻는다.

### 3. 기계 점검

- `QUALITY_BAR.md` 전 항목 통과 여부
- `BANNED_WORDS.md` 잔여 개수 (목표 0)
- 글자 수의 하한과 상한, 예외 (기준은 `SKILL.md` Stage 1)

글자 수와 금지어 개수는 눈으로 세지 않고 `python3 scripts/check.py count {자소서.md}`로 센다. 스크립트는 세기만 하고 판정은 내가 한다. 출력 끝의 눈으로 볼 것 목록(직접 인용 부호, 괄호 주석)은 문자열 검색으로 못 잡으니 원고를 읽으며 본다. 문항별 줄 아래 `짧은 문장 연속`으로 표시된 자리는 `STYLE_GUIDE.md` 어투 절 기준으로 이을지 판정한다. `도입과 마무리 겹침`으로 표시된 구절은 `STYLE_GUIDE.md` 도입 절 기준으로 마무리를 다시 쓸지 판정한다. 금지어 후보로 나온 것도 문맥이 맞는지는 `BANNED_WORDS.md` 매칭 방식 절로 판정하고, 오탐이면 스크립트를 고치지 않고 진단에 오탐이라고 적는다.

### 4. 문서 사이 정합

대조 대상은 넷이다. 확정하려는 자소서, 같은 회사 폴더의 이력 계열 산출물(`reference/resume-items.md`), `자소서/_참고/이력서-스냅샷.md`, `자소서/_참고/사실-정정.md`다. 사실 대장은 사용자가 확인해 정한 사실이라 다른 문서와 어긋나면 대장 쪽이 기준이고, 대장에 Review Needed로 남은 사실이 본문에 쓰였으면 그 자리에서 묻는다. 있는 것끼리 짝지어 대조한다. 같은 에피소드를 두 문서가 다루는데 값이 어긋나면 읽는 사람이 어느 쪽을 믿어야 할지 알 수 없게 된다.

- 수치가 같은가. 같은 지표를 다른 숫자로 적지 않았는지
- 용어가 같은가. 같은 것을 다른 이름으로 부르지 않았는지
- 팀 구성과 내 역할 범위가 같은가
- 기간이 같은가

**자소서에 안 나오는 프로젝트도 대조한다.** 이력 항목과 스냅샷에만 있는 프로젝트가 어긋나 있으면 자소서를 확정하는 자리에서 걸리지 않고 그대로 제출된다.

어긋난 자리를 양쪽 원문과 함께 보여주고 어느 쪽을 맞출지 사용자에게 묻는다. 어느 쪽이 맞는지 내가 정하지 않는다. 대조할 다른 문서가 하나도 없으면 이 검사를 건너뛰고 건너뛰었다고 한 줄 적는다.

## 출력 형식

진단은 CLI로 짧게 낸다. 파일에는 검사 결과를 쓰지 않는다.

```
## 확정 전 검사 (2번 문항, 689자 / 700자 공백 포함)

1. 문항 요구 커버 — 통과. 반드시 담을 것 3개 모두 본문에 있음
2. 뽑을 이유 한 줄 — 문의가 반복되는 이유를 기록해 두는 습관으로 월 문의를 30건에서 5건으로 줄인 사람
   문항 해석의 한 메시지와 일치
3. 기계 점검 — 금지어 잔여 0, QUALITY_BAR 4번 걸림 (5건의 기준 시점이 안 보임)
4. 문서 사이 정합 — 어긋남 1건. 팀 구성이 자소서는 5명, 이력항목.md는 4명
```

## 지적이 나와도 막지 않는다

판정이 필요한 지적(어느 쪽 사실로 맞출지, 고칠지 둘지)만 실물 문장을 붙여 묻는다. 확정할지는 묻지 않는다. 사용자가 확정이라고 할 때 승격한다. 파일이 단일 진실 소스이고 승격 판단은 사용자 몫이라는 기존 원칙을 그대로 따른다.

- 사용자가 확정하면 그대로 승격한다.
- 사용자가 지적을 인정해 고치면 그 수정을 `REVISION_LOG.md`에 유형과 하위 사유를 달아 남긴다.
- 사용자가 오탐이라고 판정하면 어느 항목이 왜 과했는지 확인하고, 반복되면 `QUALITY_BAR.md` 항목을 고칠지 제안한다.
