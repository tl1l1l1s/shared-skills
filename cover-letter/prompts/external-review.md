# 외부 검토 프롬프트 (재현용, 원문 유지)

이 프롬프트는 **사용자가 검증한 원문 그대로** 쓴다. `{회사}`만 채우고 네 기준은 바꾸지 않는다.

이 세션 밖의 다른 모델(예: Codex CLI)에 검토만 맡기는 패스다. 외부 모델은 진단과 제안만 한다. 자소서 파일은 읽기만 하고 고친 문장은 제안으로 낸다. 반영은 이 세션이 규칙대로 한다. 이 패스는 다듬기처럼 **사용자가 부를 때만** 돈다. 외부 모델이 없으면 없다고 알리고 이 패스는 건너뛴다.

## 프롬프트

> 자소서/{회사}/자소서.md 읽고
> 1. AI 티 나는 문체 점검
> 2. 문항 내 문장 구조, 문장 연결이 자연스러운지
> 3. 문항에 대한 답변이 자연스럽고 말이 되는지
> 4. 문항 내 답변 중 불필요한 미사여구, 수식 문장이 없는지

## payload (원문 뒤에 붙이는 고정 형식)

원문 블록은 손대지 않고 그 아래에 이 블록을 그대로 붙인다. 규칙 파일은 발췌하거나 요약하지 않고 경로로 준다. `{스킬 폴더}`는 이 스킬이 설치된 절대 경로로 채운다.

```
먼저 읽을 것
- 규칙은 {스킬 폴더} 의 STYLE_GUIDE.md, BANNED_WORDS.md, QUALITY_BAR.md. 금지어는 BANNED_WORDS.md 목록으로만 판정한다
- 문항과 문항 해석은 자소서/{회사}/입력.md
- 원고는 자소서/{회사}/자소서.md 의 To-Be (To-Be가 없는 문항은 As-Is). 각 문항 작업 노트의 사용자 확인 사실은 바꾸지 않는다
- 확정된 사실은 자소서/_참고/사실-정정.md (있을 때만)

하지 말 것
- 파일을 고치거나 만들지 않는다. 자소서.md 와 이력 항목 파일은 읽기만 한다
- 소재에 없는 사실과 수치와 감상을 더하지 않는다. 비면 [Review Needed]로 남긴다
- 긴 문장을 짧게 나누지 않는다. 연결어미 뒤에 콤마를 넣지 않는다. 확정된 원인에 단서를 붙이지 않는다

결과는 마지막 메시지에 문항마다 지적, 이유, 고친 문장 제안의 순서로 쓴다. 문항 전체를 다시 쓰지 않는다
```

AI 검사기 관점은 넣지 않는다. 판별기가 없어 판정하지 않는다는 답만 돌아온다.

## 실행 메모 (프롬프트 원문 아님, 스킬 동작 지침)

- **실행** 원문과 payload를 임시 파일 하나에 쓰고 외부 모델을 읽기 전용으로 돌린다. Codex CLI라면 아래와 같다. 샌드박스가 읽기 전용이라 파일 수정 금지가 프롬프트가 아니라 샌드박스로 보장되고 프로세스 종료가 곧 완료다. 시간이 걸리니 백그라운드로 돌리고 끝나면 검토 파일을 읽는다.

  ```
  codex exec -s read-only -C {자소서 폴더가 있는 작업 폴더} -o "{작업 폴더 절대 경로}/자소서/{회사}/검토-{YYYY-MM-DD}.md" - < {프롬프트 파일}
  ```

  `-o`는 절대 경로로 준다. `-C`와 달리 셸이 있던 폴더를 기준으로 경로를 찾아서 상대 경로를 주면 결과 파일 쓰기가 실패할 수 있다.

  사용량 한도에 걸리면 exec가 exit 1로 끝나고 `-o` 파일이 생기지 않는다. 로그의 ERROR 줄에 재시도 시각이 있으니 그 시각을 사용자에게 알린다.
- **돌아온 뒤 재점검** 검토 파일을 읽고 제안 문장을 반영하기 전에 아래를 본다. 외부 수정본이 이 스킬의 규칙을 되돌리기 쉬운 자리다.
  1. 연결어미 뒤 콤마
  2. 금지어와 활용형 (`python3 scripts/check.py count -`에 제안 문장을 넣어 센다)
  3. 긴 문장을 끊어 짧은 문장 연속이 늘었는지
  4. 회사 고유 근거가 빠져 회사명을 바꿔도 성립하는지 (`QUALITY_BAR.md` 6번)
  5. 사용자 확인으로 끝난 원인이나 사실에 단서가 붙었는지 (`자소서/_참고/사실-정정.md`)
  6. 당시 판단 문장이 수동형이나 사실 서술로 바뀌었는지 (`QUALITY_BAR.md` 13번)
  7. 낱말 치환으로 같은 낱말이 두 대상을 가리키게 됐는지
  8. 이력 항목 파일에 손댔는지 (`reference/resume-items.md`)
- **반영** 지적마다 재점검을 거친 제안 문장을 사용자에게 보이고 고르게 한다. 전부 반영을 고르면 그대로 To-Be에 넣는다. 전부 반영이어도 재점검에 걸린 자리는 고친 뒤에 넣고 어디를 고쳤는지 CLI에 적는다.
- **기록** `REVISION_LOG.md`에 적을 때 외부 모델의 지적을 사용자가 직접 말한 것으로 적지 않는다.
- **사용자가 직접 외부 모델을 돌려 온 검토본**도 같은 재점검을 거친다. 그 검토본이 To-Be를 이미 고쳤으면 고친 판을 제안으로 보고 같은 여덟 항목을 본다.
